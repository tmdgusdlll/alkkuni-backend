# PLANNING.md

알꾼이에서 **무엇을 만들고, 왜 그렇게 정했는지**를 정리한 문서다.
자세한 근거는 노션 설계 문서와 스파이크 보고서에 있고, 여기에는 구현할 때 바로 필요한 결정만 둔다.

## 목표

- 식약처 공공데이터를 주기적으로 수집해, 원본을 보존한 채 제품·성분 데이터를 정규화한다.
- 성분별로 제품의 1일 섭취 기준 함량을 비교할 수 있는 검색 가능한 페이지를 제공한다.
- 서랍에 담은 제품이 회수되면 중복·누락 없이 이메일로 알린다.
- 모바일 우선 반응형, 서버 렌더링(SEO)으로 검색 유입을 만든다.
- AWS 비용 월 3만원 이하, 원본(S3)으로부터 DB 재구축 가능.

## 비목표

- 개인 맞춤 추천, 효능 평가·순위, 약물 상호작용 안내 (의료 조언 영역)
- 판매량 순위 (공개 데이터 없음)
- 네이티브 앱 (반응형 웹 → PWA → 앱 순서)
- 실시간 가격 비교 (크롤링 약관 리스크)
- 식약처 신고 정보가 없는 제품(해외 직구)의 함량 비교

## 데이터 원천 (식품안전나라 OpenAPI, 인증키 하나로 호출)

| 서비스 | 용도 | 메모 |

| I0030 건강기능식품 품목제조 신고사항 | 제품 기본 정보, 함량(`STDR_STND`) | 약 4.6만 건. 파일 방식 전체 다운로드 가능 |

## 수집 파이프라인 (스파이크로 확인된 사실 기반)

- API 호출 한도: `CHNG_DT` 없이 호출하면 시간당 100회 (`INFO-320`). 에러도 HTTP 200에 본문 `RESULT.CODE`로 온다.
- 한 번에 1,000건 요청은 타임아웃. 100건은 약 0.7초.
- `CHNG_DT=YYYYMMDD`는 `LAST_UPDT_DTM` 기준으로 정확히 거른다. 신규 등록도 포함된다. 삭제 표현은 미확인.

| 작업 | 방식 | 주기 |
|---|---|---|
| 초기 적재 | 파일 방식 `/api/{key}/I0030/file` (gzip CSV 약 15MB) | 최초 1회, 장애 복구 |
| 증분 수집 | `CHNG_DT=마지막 수집일 - 1일`, 멱등 upsert | 매일 |
| 전체 대사 | 파일 방식으로 받아 해시 비교, 삭제·누락 보정 | 주 1회 또는 월 1회 |
| 회수 수집 | I0490 전체(약 400건)를 받아 이전 스냅샷과 비교. 새 건은 저장·알림, 사라진 건은 삭제하지 않고 "목록에서 빠짐" 상태 | 매일(필요하면 하루 여러 번) |

- 원본은 S3에 수집 시각 기준 경로로 저장한다.
- 수집 커서(마지막 수집일)는 DB에 저장한다.
- `INFO-320`을 받으면 재시도하지 않고 멈춘다.
- 모든 배치 작업은 스케줄과 수동(GitHub Actions workflow_dispatch → SSM) 실행을 모두 지원하고, 실행 잠금으로 겹치지 않게 한다.

## 성분 정규화

**규칙 → 실패분만 LLM → 확신도 낮은 값은 사람 검수.**

- 함량은 `STDR_STND`의 `성분명 : 표시량(숫자 단위/숫자 단위)의 80~150%` 형태에서 추출한다.
- 스파이크 결과: 추출률 80.8%, 무작위 200개 중 완전히 맞음 78.5%, 원문에 함량이 없는 제품 0.
- 파서 개선 목록 (영향 큰 순)
  1. 프로바이오틱스 균수 별도 규칙 (`1억`, `10^9`, `CFU/g`)
  2. 표시량 표기 변형 (`표시량[…]`, `｛…｝`, `표시량의(…)`, `(표시량 : 10mg / 500mg)`)
  3. "표시량" 단어 없는 형식 (`1.05mg/1,000mg의 80~180%`) → 단어가 아니라 함량 표기 모양으로 찾기
  4. 프로바이오틱스가 있으면 다른 성분까지 건너뛰는 버그를 반복하지 않기
  5. 단위가 성분명 괄호에 있는 형식 → LLM·검수 후보
  6. 분모가 단위만 있는 경우(`mg/g`)는 분모 1g
  7. 같은 제품 안에서 성분별 분모가 다르면 경고 (원문 오타 탐지)
- 분모는 대체로 1일 섭취량이지만 보장되지 않는다. 검증된 제품만 "1일 기준"으로 표시하고 나머지는 "표시 기준량당 함량"으로 표시한다(확신도로 구분).
- 정규화 사전: 단위 표기 통일(㎍/μg/ug/µg), 영양소별 환산 단위(α-TE, NE, RAE, DFE) 규칙, 성분명 동의어(셀렌=셀레늄). DB 테이블로 관리한다(Elasticsearch 아님).
- 단위 변환은 성분별 규칙으로 한다. (비타민D 1μg = 40IU, 비타민A·E는 원료 형태에 따라 다름)
- B2B 원료 품목(섭취방법에 "원료로 사용")은 비교 대상에서 뺀다.

## 회수 매칭

- 품목제조보고번호로 바로 연결되는 건은 건강기능식품 회수의 43.8%뿐이다.
- 번호가 없거나 매칭되지 않으면 제품명·제조사 기반 후보를 만들고 사람 검수 대기열로 보낸다.
- 매칭된 제품을 서랍에 담은 사용자마다 같은 트랜잭션에서 Outbox에 기록하고, 발송기가 SES로 보낸다.

## 인증

- Spring Security OAuth2 Client, 카카오·네이버·구글. 제공자를 추상화해 추가가 쉽게 한다.
- 이메일은 회수 알림에 필요하다. 이메일이 없거나 동의하지 않은 경우 로그인 후 입력받는 화면을 둔다.
- 여러 제공자로 가입한 같은 사람의 계정은 MVP에서 자동 병합하지 않는다.
- 카카오 연결 해제 웹훅·네이버 연결끊기 알림을 받으면 해당 소셜 계정과 회원 정보를 삭제한다(멱등). 공개 HTTPS 주소가 필요하므로 배포 후 등록.
- 인앱 브라우저에서 구글 로그인이 막힐 수 있다. 대응 방식은 미해결.

## 구매 링크

- 자체 API가 링크를 내려준다(링크 정책 변경, 클릭 로그, 키 보호).
- MVP는 수동 등록 링크. 쿠팡 파트너스 API는 최종 승인(누적 판매 15만원 초과) 후.
- 구매 버튼 근처에 대가성 문구를 표시하고, 수수료가 순위·노출에 영향을 주지 않는다.

## 배포

- 프론트·백엔드 레포와 CI/CD 분리. 이미지 태그는 커밋 해시, EC2 `.env`의 `WEB_TAG`/`API_TAG`로 관리.
- 배포는 서비스 단위 교체(`docker compose pull api && docker compose up -d --no-deps api`). `docker compose down`은 배포에 쓰지 않는다.
- CI/CD 단계: (1) 테스트·빌드·ECR 푸시 → (2) SSM으로 교체 → (3) 헬스 체크(`/actuator/health`) 실패 시 직전 태그로 자동 롤백.
- 컨테이너별 `mem_limit`, JVM 힙 크기 조정. 2GB가 부족하면 t4g.medium 검토.
